# 借鉴 gpui-kit 生态产品：评估报告

日期：2026-10-15 · 基于 v0.2.2（`release/v0.2.2`）

来源：<https://gpui-kit.com/apps/> 列出了 80 个应用，第一页可见 15 个。与 DuckLocal 最接近的几个已克隆下来逐个读过源码：

| 应用 | 定位 | 可借鉴程度 |
| --- | --- | --- |
| **Zedis** (vicanso/zedis) | Redis GUI，约 17 万行，生态里打磨最细的数据工具 | 高：键盘流、诊断、首启引导 |
| **RustGrid** (yisier/rustgrid) | 仿 Navicat 的数据库 GUI | 中：结果网格的复制格式、已保存查询 |
| disktree / Wake / tty7 等 | 磁盘、会话浏览、终端 | 低：领域不同 |

原则：不改变现有功能和视觉风格。小而纯增量的部分已直接实现（见第一节），大的改动列在第二节，由你决定。

## 二、值得做但改动较大，请你决定

按"收益 ÷ 成本"从高到低排列。

### 1. 崩溃报告和日志文件 ✅ 已实现（2026-10-15）

**现状：** Windows 发行版的 GUI 没有控制台窗口，`tracing_subscriber::fmt()` 输出到 stderr，等于全部丢弃；panic 后窗口直接消失，用户报 bug 时没有任何东西可以附上。

**Zedis 的做法**（`helpers/crash.rs`，261 行）：
- panic hook 把报告**同步**写到 `<logs>/crash-<时间戳>.log`，内容包括版本、git sha、OS/arch 和 backtrace，同时留下一个 `crash.pending` 标记；
- 下次启动看到标记，就弹出一张卡片，指向这份报告；
- 日志按天滚动写文件，菜单里有"打开日志文件夹"，约 3 个月后自动清理；
- "导出诊断信息"：把日志、崩溃报告和脱敏配置打成一个 zip 放到下载目录。

**建议范围：** 前两项（panic hook + 下次启动提示）约 200 行，再加"打开日志文件夹"菜单项。zip 导出可以先不做。
**风险：** 会动启动路径（`main.rs`），需要在三个平台上验证。

### 2. 退出时保留未保存的查询标签页 ✅ 已实现（2026-10-15，无开关）

**现状：** 仪表盘标签页会被记住（`remember_dashboards`），查询标签页里**还没运行过的 SQL** 在退出后丢失；运行过的能在历史里找到，但标签页的排列和标题都没了。

**Zedis 的做法：** 记住打开的标签页列表，下次启动时恢复，后台标签页延迟加载。

**建议范围：** 把每个查询标签页的 `{title, sql}` 和当前激活的序号写进现有的 settings 存储，启动时恢复；与 `spec::tabs::remember` 并列。约 100–150 行。
**需要你决定：** 这会改变"启动时是一个空查询标签页"的现有行为。是否要加开关？

### 3. ⌘K 命令面板

**Zedis 的做法**（`views/command_palette.rs`，851 行）：模糊搜索服务器、面板和已加载的键，方向键选择，回车执行，Esc 退出。另有 ⌘P 打开最近的键。

**对应到 DuckLocal：** 一个入口模糊搜索
- 所有菜单命令（运行、格式化、EXPLAIN、Profile、导出、切换侧边栏……）；
- 表和列，回车生成 `SELECT` 到新标签页（复用侧边栏已有的动作）；
- 最近的仪表盘（`recents`）和已打开的标签页。

**成本：** 新的浮层组件，约 500–800 行，并且要设计视觉样式。这是一个新的 UI 界面，不只是优化，所以交给你决定。
**收益：** 表很多时，比在侧边栏树里滚动快得多；也解决了命令藏在 `+` 菜单和工具栏里不好发现的问题。

### 4. ⌘/ 快捷键速查浮层

**Zedis：** `views/shortcuts_overlay.rs`（239 行），一个只读、按组排列、显示各平台符号的浮层。
**DuckLocal：** 快捷键目前只体现在 macOS 菜单栏里，Windows 和 Linux 用户几乎无从发现。
**成本：** 小到中，约 200 行，复用现有的 `Kbd` 组件。也算新的 UI 界面，所以列在这里。

### 5. 标签页右键菜单：关闭其他 / 关闭右侧，以及拖动排序 ✅ 已实现（2026-10-15）

**Zedis：** 右键菜单提供关闭、关闭其他、关闭右侧；标签页可以拖动排序。
**成本：** 需要确认 gpui-kit 的 `TabBar` / `Tab` 是否支持 `context_menu` 和拖放，可能要自己包一层。约 100 行。关闭时要沿用现有的"有未保存修改的仪表盘先询问"逻辑。

### 6. 结果"复制为…"：Markdown、JSON、INSERT 语句

**RustGrid** 有 "Copy as INSERT"。DuckLocal 的用户经常把结果贴进 issue、文档或 AI 对话，Markdown 表格和 JSON 会比制表符分隔的文本更有用。
**成本：** 在第一节已实现的右键菜单里加一个子菜单，加上格式化函数和测试，约 150 行。
**需要你决定：** 菜单会变长。是否只对"整个结果 / 选中行"提供这些格式？

### 7. 首次启动引导 ✅ 已实现（2026-10-15，鸭子 + 箭头的 5 步引导，`src/ui/tour.rs`）

**Zedis：** 首次启动显示三步欢迎卡片，有学习门槛的面板第一次打开时显示一次性提示，之后不再出现。
**DuckLocal 现状：** 结果区已有空状态提示（"输入 SQL，按 ⌘↵ 运行"）。还缺"没有打开任何数据"时的引导，比如"拖入文件 / 打开示例数据"。
**需要你决定：** 涉及视觉设计。按记忆里的原则（宣传要靠真实能力，要胜过"直接用 Excel"），这里可以放一个"打开示例数据"按钮，加载 `examples/` 里的订单数据，30 秒内就能体验到价值。

## 三、看过但不建议做

| 项目 | 原因 |
| --- | --- |
| Zedis 的 6 套主题配色、可选 UI 和等宽字体 | 会改变设计风格，违背本次的前提 |
| 应用内自更新（下载、校验 SHA-256、原地替换） | 已有更新检查；做原地替换牵涉签名和公证，成本高，而且与"功能冻结，主线是 DuckDB 2.0"冲突 |
| RustGrid 的就地编辑网格 | DuckLocal 查询的多是只读文件，就地编辑的语义不清楚 |
| 系统托盘、HTTP 代理设置 | 与本地数据工具的定位关系不大 |
| GPUI Fast 渲染后端（Zedis 在试用） | 还在试验阶段，Zedis 测得 CPU 约低 20%、内存约高 20%，等 gpui-kit 稳定后再评估 |
