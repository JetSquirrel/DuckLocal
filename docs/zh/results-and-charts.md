# 结果与图表

**[English](../results-and-charts.md)** · [文档](index.md)

编辑器下方的面板有两个 Tab：**结果** 和 **图表**。

## 结果表格

表格最左侧是一列 `#` 行号，之后是你的各个列。数值列右对齐，列宽可以拖拽调整。`#` 列不能调整宽度。

**不支持排序。** 点击表头不会有任何作用——请在 SQL 中用 `ORDER BY` 排序。

### 单元格渲染

| 值 | 显示为 |
| --- | --- |
| `NULL` | 字面量 `NULL`，颜色淡化显示 |
| BLOB | `<blob N bytes>` |
| GEOMETRY | `<geometry N bytes>` |
| 整数值浮点数 | `3.0` |
| 时间戳 | `2026-09-17 04:21:09`——**UTC 时间，不是本地时间** |
| List / struct / map | 格式化输出 |

如果你是用肉眼查看时间戳，而不是在 SQL 中比较它们，那么要记住这里是按 UTC 渲染的。

### 过滤

过滤框会对已加载行的**所有单元格**做不区分大小写的子串匹配。它是纯客户端的：不会查询数据库，统计的是已加载的行数，而不是真实的结果规模。

过滤在你按下 Enter 或清空输入框时生效，而不是每敲一个键就生效。它旁边会显示 `visible / total rows`。

## 行数上限

结果会在以下两个上限中先触发的那个处截断：

- **100,000 行**
- **2,000,000 个单元格**——因此一个 400 列的结果只会实际生成约 5,000 行

之所以有单元格预算，是因为仅靠行数上限无法约束计算量：对一个高基数列做 `PIVOT` 会为每个不同的值返回一列，而格式化上千万个单元格会看起来像是卡死。

截断会通过一条横幅提示，其中给出实际生成的行数。**没有分页，也没有“加载更多”**——请改为缩小查询范围。

## 复制

鼠标悬停在单元格上会显示一个复制按钮，点击后将该单元格的文本放入剪贴板。这是唯一的复制方式：没有整行复制、没有区域选择、没有“复制为 SQL”，也没有右键菜单。

## 导出

`导出 CSV` 和 `导出 Parquet` 会打开一个小对话框，其中有一个路径字段，预填为 `~/Desktop/export.csv` 或 `~/Desktop/export.parquet`。

有两点需要注意：

- 导出会**重新运行生成当前结果行的 SQL**，因此文件中保存的是查询的完整结果集——不是筛选后的视图，也不是截断后的表格。
- 没有文件选择器，也没有覆盖确认。输入路径后即写入。

## 图表

图表基于结果表格中已有的行绘制，顺序与查询返回的顺序一致。**不做任何聚合**——它们不是 `GROUP BY` 图表。

图表类型会根据第一列自动选择：

| 第一列 | 图表 |
| --- | --- |
| 时间类型（date / timestamp） | 面积图；x 轴为第 0 列，每个数值列一条序列 |
| 其他 | 柱状图；第 0 列作为标签，第一个数值列作为值 |

值单元格不是数值的行——例如 `NULL`——会在绘图前被丢弃。

各项限制都会在图表标题下方的提示行中说明：

| 限制 | 行为 |
| --- | --- |
| 12 条序列 | 多余的数值列会被丢弃 |
| 1,500 个数据点 | 序列会被分桶，并在每个桶内取**平均值** |
| 200 根柱子 | 多余的柱子会被截断，而不是合并 |

标题始终会标明绘制了多少个数据点，因此在相信曲线形状之前请先核对它。
